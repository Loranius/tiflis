# Tiflis semantic code workflow

Use the `serena` MCP for code tasks where symbols, references, ownership, or cross-file behavior matter.

## Retrieval order

1. Activate the Tiflis project and read Serena's initial instructions.
2. Use a symbol overview for the smallest relevant file or module.
3. Locate the exact component, hook, function, type, or constant with symbol search.
4. Retrieve only the symbol bodies needed for the task.
5. Find referencing symbols before renaming, moving, deleting, or changing a public contract.
6. Read whole files only when structure cannot be understood symbolically.

## Editing order

- Prefer symbol rename for semantic renames.
- Prefer replace-symbol-body for contained behavior changes.
- Prefer insert-before/after-symbol for adjacent additions.
- Use text replacement only for non-symbolic content such as CSS declarations, prose, fixtures, or generated configuration.
- Run diagnostics after edits and fix new errors before moving on.

## Tiflis rules

- Inspect both frontend callers and Supabase Edge Function handlers when changing an API action or response shape.
- Preserve permissions and restricted cash-data boundaries.
- Do not edit `stable-runtime` by hand; it is generated by the deployment workflow.
- Avoid broad search-and-replace across Ukrainian labels because identical text may serve different flows.
- Run `npm run typecheck`, `npm run build`, `npm run perf:budget`, and `npm run smoke:dist` after production changes.
