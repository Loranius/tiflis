# Staff v1

П’ятий повністю перенесений модуль Tiflis v2.

## Робочий простір команди

- пошук і фільтрація за ролями;
- активна команда та окремий архів;
- основна й друга роль;
- профіль, нікнейм, avatar, день народження, credo;
- Instagram і Telegram username;
- статус фактичної Telegram-прив’язки;
- найближча зміна та кількість змін за поточний місяць;
- саморедагування без доступу до адміністративних полів;
- адміністративне редагування ролей, стажування й права на сповіщення.

## Захищені акаунти

- нові працівники створюються одразу в Supabase Auth;
- тимчасовий пароль показується адміністратору лише один раз;
- у `users.password` зберігається непридатний випадковий маркер;
- `credential_source=auth` позначає Supabase Auth як джерело істини;
- після першої міграції legacy-пароль автоматично знищується й замінюється маркером;
- наступні входи перевіряються напряму через Supabase Auth;
- адміністратор може видати новий тимчасовий пароль, але не переглянути чинний.

## Життєвий цикл

- звільнення — це деактивація й перенесення в архів;
- hard-delete працівників не використовується, щоб не руйнувати графік, касу, резерви та аудит;
- `sysadmin` захищений від архівації та змін стороннім адміністратором;
- адміністратор не може деактивувати сам себе.

## Серверна архітектура

- окремий JWT-захищений `tiflis-staff-api`;
- `tiflis-auth-migrate` підтримує два шляхи: перша legacy-міграція та auth-only login;
- жоден API не повертає поле `password`;
- створення Auth-користувача, legacy-профілю й `staff_profiles` супроводжується компенсаційним rollback при помилці.

## Відкинуті рудименти

- показ паролів у таблиці персоналу;
- редагування робочого пароля через браузер;
- hard-delete працівника;
- локальний кеш персоналу як джерело істини;
- глобальні onclick та HTML templates;
- окрема сторінка Telegram-довідника, яка дублює профілі.
